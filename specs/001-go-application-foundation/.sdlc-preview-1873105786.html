Acceptance Criteria

AC001.1 - Exodan configuration

Criterion
Given supplied runtime paths, the application merges defaults, host YAML, and secrets in that order and uses the resulting application values. The documented host configuration supplies the public base_url that Exodan reads for Caddy routing and DNS; the listener still uses ADDR independently.
Proven by
RT001.1 - Layered configuration.

AC001.2 - Invalid configuration fails visibly

Criterion
Given a missing required value, malformed application value, or unreadable explicitly supplied layer, startup fails before listening and identifies the field or layer without disclosing its value. This covers configuration loading and application-owned settings, not URL or domain validation.
Proven by
RT001.1 - Layered configuration.

AC001.3 - Configured listener and page

Criterion
Given valid configuration, serve binds the supplied ADDR and serves an HTML landing page and local CSS. The page's canonical link uses the supplied base_url independently of request headers or the listener address.
Proven by
RT001.2 - Executable HTTP boundary.

AC001.4 - Persistent state survives restart

Criterion
Given an existing application database, restarting preserves its state and applies each supported migration once.
Proven by
RT001.3 - Storage lifecycle.

AC001.5 - Unusable storage prevents operation

Criterion
Given unavailable storage, a newer unsupported schema, or a failed migration, the application does not accept work against that state.
Proven by
RT001.3 - Storage lifecycle.

AC001.6 - Truthful health

Criterion
The health endpoint returns 200 only when required storage and schema are usable; dependency failure returns 503 without configuration or database details.
Proven by
RT001.4 - Health reflects storage.

AC001.7 - Safe CLI behaviour

Criterion
Help and version requests exit successfully without runtime configuration or writes. Invalid invocation exits 2; operational failure exits 1.
Proven by
RT001.5 - CLI outcomes.

AC001.8 - Bounded server lifecycle

Criterion
Requests and shutdown respect the specified size and time bounds. A normal termination closes the listener and database without accepting further work.
Proven by
RT001.6 - Limits and shutdown.

AC001.9 - Accessible page without JavaScript

Criterion
The landing page works without JavaScript, has semantic structure and visible keyboard focus, and remains readable at 320 CSS pixels and 200% zoom. Apply WCAG 2.1 AA: text contrast at least 4.5:1, or 3:1 for large text; keyboard access, meaningful labels/alt text, one h1 and ordered headings are required.
Proven by
RT001.2 - Executable HTTP boundary; UT001.1 - Landing-page usability.

AC001.10 - Portable build and verification

Criterion
Repository-owned commands build, install locally, lint, test, and check vulnerabilities with failures propagated. Repeating local installation preserves the same installed content and unrelated files. The application can be cross-compiled for Linux amd64 without a target Go installation.
Proven by
OT001.1 - Build and tooling contract.

Test Definitions

RT001.1 - Layered configuration

Covers
AC001.1 - Exodan configuration; AC001.2 - Invalid configuration fails visibly.
Boundary
The configuration loader and executable startup.
Setup
Temporary defaults, host, and synthetic secrets files with overlapping scalar and nested values; cases with absent optional paths, an empty explicit file, malformed YAML, wrong types, missing required fields, and unreadable paths. Use distinct synthetic default and host URLs, with credentials only in the secrets layer and a separate loopback ADDR.
Action
Load the layers and start the executable with each invalid case.
Expected
Rightmost supplied values win, omitted values remain inherited, optional absent layers are allowed, and all invalid cases fail before listener readiness. The host URL becomes the configured public URL independently of ADDR; the secrets layer preserves it. Diagnostics contain field names but no synthetic secret values. Unrelated Exodan keys are tolerated.
Scope boundary
Check consumption of the supplied base_url; do not add application URL-policy checks, domain verification, DNS queries, or deployment probes.
Retention
Persistent standard Go regression suite through make test; written before the implementation and observed RED.

RT001.2 - Executable HTTP boundary

Covers
AC001.3 - Configured listener and page; AC001.9 - Accessible page without JavaScript.
Boundary
Requests to the built executable on an OS-assigned loopback port.
Setup
Temporary runtime tree and database, with test-owned valid HTML templates and a small CSS/static fixture matching the packaged paths; one IPv4 case and one IPv6 loopback case on a host supporting both. Use separate absent/malformed template copies for failure cases.
Action
Wait for observable readiness, request the root page, CSS, an unknown path, and an unsupported method; repeat with templates absent or malformed.
Expected
Correct HTML/CSS content types, local asset links, one h1, labelled navigation, no script-dependent interaction, 404/405 for invalid routes, and startup failure when required templates cannot be parsed. Listener address matches ADDR; the canonical link equals configured baseurl even under a different request Host.
Retention
Persistent standard Go regression suite through make test; written before the implementation and observed RED.

RT001.3 - Storage lifecycle

Covers
AC001.4 - Persistent state survives restart; AC001.5 - Unusable storage prevents operation.
Boundary
Store initialization using a real local SQLite database.
Setup
Fresh, initialized, unsupported-newer, read-only, and deliberately failed-migration databases in test-owned directories. Supply a test-owned migration that creates a small parent/child table; this fixture does not add a production domain table.
Action
Initialize twice, insert and reopen a fixture row, and exercise the failure cases through the migration/store boundary. The migration runner accepts an explicit ordered migration collection, enabling a failing fixture without a production test switch.
Expected
Persistence survives restart, migration version advances only after commit, repeated initialization is harmless, and failures preserve the previous committed schema and data. Foreign-key violations fail on every pooled connection.
Retention
Persistent standard Go regression suite through make test; written before the implementation and observed RED.

Covers

200 with {"status":"ok"} when ready; 503 with {"status":"unavailable"} afterwards; neither response exposes paths, configuration, or SQL errors.

RT001.5 - CLI outcomes

Covers
AC001.7 - Safe CLI behaviour.
Boundary
Executable process, exit status, stdout, stderr, and temporary-directory contents.
Setup
No runtime configuration; help/version, unknown command, unknown flag, and malformed serve configuration cases.
Action

RT001.6 - Limits and shutdown

Covers
AC001.8 - Bounded server lifecycle.
Boundary
HTTP requests and termination of the executable.
Setup
Temporary runtime with short test-configured timeouts. Use the shared HTTP-server constructor with test-owned handlers to hold a request body or response at synchronization points; separately exercise process termination through the executable.
Action
Exceed the header bound; stall headers, body reads, response writes and idle keep-alive connections in separate cases; then terminate during an active request. These are real socket interactions, not assertions about timeout field values.
Expected
Oversized headers and timeout cases are rejected or disconnected, accepted work receives only its configured grace period, the listener closes, and the database can be reopened. Successful draining exits 0; expiry of shutdown grace exits 1 with a safe diagnostic. No fixed sleep is used as readiness evidence.
Retention
Persistent standard Go regression suite through make test; written before the implementation and observed RED.

Edge Cases

  • A supplied but unreadable configuration layer fails startup, even if lower layers contain usable values. Covered by AC001.2 - Invalid configuration fails visibly.
  • A database created by a newer application version is not downgraded. Covered by AC001.5 - Unusable storage prevents operation.
  • A dependency failure after startup changes health to unavailable. Covered by AC001.6 - Truthful health.
  • An IPv6 address is passed intact to the listener. Covered by AC001.3 - Configured listener and page.
  • Help and version requests do not initialize storage. Covered by AC001.7 - Safe CLI behaviour.

Solution Design

Architecture context

Components
cmd/stv-poll, internal/config, internal/store, and internal/web.
Reuse
Adapt upload's layered configuration and writeback's explicit application wiring, cached templates, migration pattern, and bounded HTTP lifecycle. Preserve source provenance and applicable licence obligations. Do not copy their domain schemas or legacy configuration fallbacks.
Dependency direction
The entry point constructs typed configuration, store, templates, and HTTP handlers. Handlers do not access environment variables or execute SQL.

High-level design

Flow

  1. Parse invocation; help and version return before configuration.
  2. Load and validate YAML, initialize the database transactionally, and parse templates.
  3. Bind the supplied address and serve until cancellation.
  4. Stop accepting requests, allow bounded draining, and close owned resources.

Interfaces and configuration

Commands
stv-poll serve, stv-poll -h, stv-poll --help, and stv-poll --version. No successful placeholder process-due-work command; W003 adds that operation.
Routes
GET / serves the landing page; GET /healthz returns the JSON health contract; GET /static/* serves only packaged public assets. Unsupported methods return 405; unknown routes return 404.
Runtime paths
DEFAULT_CONFIG_PATH and STATE_DIRECTORY are required for serve; CONFIG_PATH and SECRETS_PATH are optional when absent, mandatory to read when explicitly supplied. ADDR is required. Relative runtime asset paths resolve from process cwd.
Compatibility
This new application deliberately requires DEFAULTCONFIG_PATH and does not implement Exodan's fallback for older applications. Exodan supplies this variable to the service, admin wrapper and timers. Local instructions supply it explicitly; omission fails before listening.
YAML
Consume the required base_url string supplied through Exodan configuration for link construction. The application does not validate the URL or domain or impose scheme, host, or deployment policy. Known application settings are type-checked; unrelated Exodan keys remain tolerated.
HTTP settings
Use the exact duration keys and defaults in the table below. Durations are positive Go duration strings; zero, negative, empty, and malformed supplied durations fail startup. The header maximum is fixed at 64 KiB.
Configuration layering
Recursively merge maps; a supplied scalar or sequence replaces its previous value. Reject non-string map keys, incompatible known types, and null required values. Do not use legacy environment overrides for application values.
Assets
Declare templates and static in data_dirs; cache parsed templates at startup. Their absence or syntax error is a startup failure.
Application YAML key Default / contract
baseurl Required non-empty string, consumed for links without URL/domain validation.
http.readheader_timeout 5s
http.readtimeout 15s
http.writetimeout 15s
http.idletimeout 60s
http.shutdowntimeout 10s
Configuration parsing
Use gopkg.in/yaml.v3. Accept one mapping document per layer; an empty optional document is an empty overlay. Reject duplicate keys, non-string keys, malformed YAML, and multiple documents. Defaults must be a non-empty mapping. Unknown keys are tolerated for Exodan and later application features.
Example and loading
The example below is complete for foundation startup when runtime paths and ADDR are supplied. Load configuration once per process; changes take effect on restart. Neither serve nor a later worker rewrites configuration or decrypts age files. 
# config/defaults.yaml; illustrative base_url only
base_url: https://polls.example.com
data_dirs: [templates, static]
http:
  read_header_timeout: 5s
  read_timeout: 15s
  write_timeout: 15s
  idle_timeout: 60s
  shutdown_timeout: 10s
Regression detail
RT001.1 exercises every duration key, duplicate keys, multiple documents, an empty optional overlay, and a required empty defaults file. Its expected outcomes follow these parsing rules; no URL-policy cases are added.
Page and assets
The landing page identifies STV Poll and explains that it collects ranked preferences; it contains no non-working poll controls. Package CSS and a generic Open Graph image under static/. Include semantic HTML, language/viewport metadata, and generic Open Graph metadata. Reject traversal and symlinks escaping the public asset root; RT001.2 covers those requests and a missing asset without exposing state/configuration files.

Public URL and deployment handoff

Primary domain
Exodan reads base_url from the app's config/<host>.yaml for Caddy routing and DNS. Supply the same public URL to the application through CONFIG_PATH; DEFAULT_CONFIG_PATH supplies the base layer. Keep deployment domain settings in non-secret configuration, not in a secrets-only override that Exodan's domain discovery cannot see.
Ownership
These declarations describe the integration handoff. Exodan owns URL/domain validation and infrastructure configuration. The application reads the supplied values, constructs its links, and binds ADDR; it does not verify or reconcile the deployment.
Listener
ADDR is the infrastructure-supplied internal bind address. It does not set the public URL, scheme, or port used in invitations. The application does not allocate a deployment port or terminate public TLS.
Configuration artefacts
Implementation supplies config/defaults.yaml, config/localhost.yaml.example, and a documented host example. A real config/<host>.yaml with the operator-selected domain is required before deployment. No hostname, domain registration, or live deployment is selected by this specification.
Host example
The following values are illustrative placeholders only. The host filename identifies the Exodan deployment target; base_url identifies the public application endpoint. 
# config/<host>.yaml, after substituting the selected public domain
base_url: https://polls.example.com
Base assets
Declare the following in config/defaults.yaml alongside its required base_url. 
data_dirs:
  - templates
  - static
Additional domains
Exodan's optional extra_domains setting belongs to its routing contract. It does not change the application's canonical link origin. This build requires one primary domain; it makes no alias or path-prefix deployment claim.
Deployment prerequisite
The operator configures the application and serve invocation in Exodan, chooses the target host and public domain, and supplies encrypted secrets when W003 needs them. The app documentation points to that handoff without creating infrastructure configuration or running deployment commands.

Data and state

Database
STATE_DIRECTORY/stv-poll.sqlite using database/sql and modernc.org/sqlite. Apply the SQLite dependency assessment; retain pinned module versions and go.sum, preserve licence/provenance obligations, and review the driver's coupled libc version on upgrades. The assessment records maintenance, alternatives and security/operational risks; it is not vulnerability-scan evidence.
Connection policy
Enforce foreign keys on every connection, a 5-second busy timeout, and one connection per process. Use SQLite's default rollback-journal mode initially. Later independent web/worker processes coordinate through write transactions. A health check has a separate 500 ms context deadline.
Migration ownership
Embedded, ordered migrations and a schema-version record. Apply an outstanding migration and its version update in one transaction, serializing initialization. No poll-domain tables are introduced by this ticket.
Permissions
Exodan owns the state directory, identity, ownership and access policy. The app requires the supplied directory to exist and be writable; it does not create/chmod/chown infrastructure directories. Create its database with mode 0600 and preserve existing file modes. Never serve state paths as static assets. Local development instructions create an operator-owned temporary state directory.

Failure behaviour

  • Startup failures exit 1 with safe context. Invocation errors exit 2; unknown flags are not ignored.
  • Health uses a bounded store check and returns its small documented response. Detailed diagnostics remain in structured stderr logs with credentials and data redacted.
  • Cancellation propagates to owned work. Successful draining exits 0; shutdown-grace expiry closes remaining connections and exits 1. Both paths release the database and emit safe structured stderr diagnostics.

Build and verification contract

Commands
make build, make install, make lint, make test, make vulncheck, and the SDLC-defined operator-only make sync.
Local installation
make install builds, installs the executable at PREFIX/bin/stv-poll, and copies templates, static assets and non-secret defaults under PREFIX/share/stv-poll/. PREFIX defaults to the repository's ignored .local/ directory. Repeated installation updates only these managed paths, preserves unrelated files, and never installs plaintext secrets or host configuration. Document serve from the installed asset directory with explicit runtime variables. No privileged/global installation or deployment is implied.
Build
Use module path github.com/tigger-developer/Instant-Runoff-Polls-PR-STV- and entry point cmd/stv-poll. Produce the local executable under ignored bin/; document Linux cross-compilation with CGo disabled. Do not install a target-side toolchain. Keep CLI help in docs/stv-poll-help.md and package it at build time; version output includes the build revision, or dev for an untagged local build.
Lint
Apply gofmt checking, go vet, golangci-lint with the Go standard's required checks, standalone Biome for CSS linting/format checking, and tidy-html5 diagnostics for rendered HTML without rewriting output. Oxlint applies to project-owned JavaScript/TypeScript if such source is later approved; none is introduced by this specification. Provision native tool versions explicitly outside check targets.
Rendered-HTML coverage
The lint entry point obtains application-rendered pages using the existing Go rendering/HTTP facilities and synthetic local state. It validates the emitted HTML, not unexpanded Go templates. W003 extends this coverage to its page/form states; no browser automation or separate rendering stack is introduced.
Test
Retained behavioural RTs only; use the race detector for concurrent code. Apply the SDLC coverage floor and complete branch evidence for durable state changes.
Security gate
govulncheck ./... plus any additional applicable dependency set introduced by build tooling. The target installs nothing, changes no locks, fails on missing tooling or incomplete scans, and remains separate from make test.
Tooling dependencies
Use standalone Biome and tidy-html5 for the owned CSS and rendered HTML, with no Node.js dependency. Enable Biome's CSS linter and formatter in project configuration. Record exact tool versions, platform artefacts and checksums during delivery; provision them outside check targets through approved native distributions. Missing applicable tooling fails the check. No browser JavaScript, bundler or browser automation is introduced; oxlint is conditional on a later approved JavaScript/TypeScript source dependency.
Tooling security
Run govulncheck ./... through make vulncheck for the Go application dependencies. Checks do not install tools, edit locks or apply fixes. Pin and verify the standalone CSS tool separately; no package-manager dependency graph is introduced for linting. OT001.1 verifies missing-tool and scanner failure propagation.

The subsequent instruction selects the SDLC-recommended oxlint, tidy-html5 and Biome according to the source types owned by the project. Ignore rules
Ignore binary output, local plaintext secrets, caches, and entire project-local agent runtime directories. Keep module checksums tracked.
