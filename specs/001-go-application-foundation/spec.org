* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:

** Architecture context

- Components :: =cmd/stv-poll=, =internal/config=, =internal/store=, and =internal/web=.
- Reuse :: Adapt upload's layered configuration and writeback's explicit application wiring, cached templates, migration pattern, and bounded HTTP lifecycle. Preserve source provenance and applicable licence obligations. Do not copy their domain schemas or legacy configuration fallbacks.
- Dependency direction :: The entry point constructs typed configuration, store, templates, and HTTP handlers. Handlers do not access environment variables or execute SQL.

** High-level design

*** Flow

1. Parse invocation; *help and version return before configuration*.
2. Load and validate YAML, initialize the database transactionally, and parse templates.
3. Bind the supplied address and serve until cancellation.
4. Stop accepting requests, allow bounded draining, and close owned resources.

*** Interfaces and configuration

- Commands :: =stv-poll serve=, =stv-poll -h=, =stv-poll --help=, and =stv-poll --version=. No successful placeholder =process-due-work= command; W003 adds that operation.
- Routes :: =GET /= serves the landing page; =GET /healthz= returns the JSON health contract; =GET /static/*= serves only packaged public assets. Unsupported methods return 405; unknown routes return 404.
- Runtime paths :: =DEFAULT_CONFIG_PATH= and =STATE_DIRECTORY= are required for serve; =CONFIG_PATH= and =SECRETS_PATH= are optional when absent, mandatory to read when explicitly supplied. =ADDR= is required. Relative runtime asset paths resolve from process cwd.
- Compatibility :: This new application deliberately requires DEFAULT_CONFIG_PATH and does not implement Exodan's fallback for older applications. Exodan supplies this variable to the service, admin wrapper and timers. Local instructions supply it explicitly; omission fails before listening.
- YAML :: Consume the required =base_url= string supplied through Exodan configuration for link construction. The application does not validate the URL or domain or impose scheme, host, or deployment policy. Known application settings are type-checked; unrelated Exodan keys remain tolerated.
- HTTP settings :: Use the exact duration keys and defaults in the table below. Durations are positive Go duration strings; zero, negative, empty, and malformed supplied durations fail startup. The header maximum is fixed at 64 KiB.
- Configuration layering :: Recursively merge maps; a supplied scalar or sequence replaces its previous value. Reject non-string map keys, incompatible known types, and null required values. Do not use legacy environment overrides for application values.
- Assets :: Declare =templates= and =static= in =data_dirs=; cache parsed templates at startup. Their absence or syntax error is a startup failure.

| Application YAML key | Default / contract |
|----------------------+--------------------|
| base_url | Required non-empty string, consumed for links without URL/domain validation. |
| http.read_header_timeout | 5s |
| http.read_timeout | 15s |
| http.write_timeout | 15s |
| http.idle_timeout | 60s |
| http.shutdown_timeout | 10s |

- Configuration parsing :: Use =gopkg.in/yaml.v3=. Accept one mapping document per layer; an empty optional document is an empty overlay. Reject duplicate keys, non-string keys, malformed YAML, and multiple documents. Defaults must be a non-empty mapping. Unknown keys are tolerated for Exodan and later application features.
- Example and loading :: The example below is complete for foundation startup when runtime paths and =ADDR= are supplied. Load configuration once per process; changes take effect on restart. Neither =serve= nor a later worker rewrites configuration or decrypts age files.

#+begin_src yaml
# config/defaults.yaml; illustrative base_url only
base_url: https://polls.example.com
data_dirs: [templates, static]
http:
  read_header_timeout: 5s
  read_timeout: 15s
  write_timeout: 15s
  idle_timeout: 60s
  shutdown_timeout: 10s
#+end_src

- Regression detail :: RT001.1 exercises every duration key, duplicate keys, multiple documents, an empty optional overlay, and a required empty defaults file. Its expected outcomes follow these parsing rules; no URL-policy cases are added.
- Page and assets :: The landing page identifies STV Poll and explains that it collects ranked preferences; it contains no non-working poll controls. Package CSS and a generic Open Graph image under =static/=. Include semantic HTML, language/viewport metadata, and generic Open Graph metadata. Reject traversal and symlinks escaping the public asset root; RT001.2 covers those requests and a missing asset without exposing state/configuration files.

*** Public URL and deployment handoff

- Primary domain :: Exodan reads =base_url= from the app's =config/<host>.yaml= for Caddy routing and DNS. Supply the same public URL to the application through =CONFIG_PATH=; =DEFAULT_CONFIG_PATH= supplies the base layer. Keep deployment domain settings in non-secret configuration, not in a secrets-only override that Exodan's domain discovery cannot see.
- Ownership :: These declarations describe the integration handoff. Exodan owns URL/domain validation and infrastructure configuration. The application reads the supplied values, constructs its links, and binds =ADDR=; it does not verify or reconcile the deployment.
- Listener :: =ADDR= is the infrastructure-supplied internal bind address. It does not set the public URL, scheme, or port used in invitations. The application does not allocate a deployment port or terminate public TLS.
- Configuration artefacts :: Implementation supplies =config/defaults.yaml=, =config/localhost.yaml.example=, and a documented host example. A real =config/<host>.yaml= with the operator-selected domain is required before deployment. No hostname, domain registration, or live deployment is selected by this specification.
- Host example :: The following values are illustrative placeholders only. The host filename identifies the Exodan deployment target; =base_url= identifies the public application endpoint.

#+begin_src yaml
# config/<host>.yaml, after substituting the selected public domain
base_url: https://polls.example.com
#+end_src

- Base assets :: Declare the following in =config/defaults.yaml= alongside its required =base_url=.

#+begin_src yaml
data_dirs:
  - templates
  - static
#+end_src

- Additional domains :: Exodan's optional =extra_domains= setting belongs to its routing contract. It does not change the application's canonical link origin. This build requires one primary domain; it makes no alias or path-prefix deployment claim.
- Deployment prerequisite :: The operator configures the application and =serve= invocation in Exodan, chooses the target host and public domain, and supplies encrypted secrets when W003 needs them. The app documentation points to that handoff without creating infrastructure configuration or running deployment commands.

*** Data and state

- Database :: =STATE_DIRECTORY/stv-poll.sqlite= using =database/sql= and =modernc.org/sqlite=. Apply the [[file:../../docs/ARCHITECTURE.md::#sqlite-dependency-assessment][SQLite dependency assessment]]; retain pinned module versions and =go.sum=, preserve licence/provenance obligations, and review the driver's coupled libc version on upgrades. The assessment records maintenance, alternatives and security/operational risks; it is not vulnerability-scan evidence.
- Connection policy :: Enforce foreign keys on *every connection*, a 5-second busy timeout, and one connection per process. Use SQLite's default rollback-journal mode initially. Later independent web/worker processes coordinate through write transactions. A health check has a separate 500 ms context deadline.
- Migration ownership :: Embedded, ordered migrations and a schema-version record. Apply an outstanding migration and its version update in one transaction, serializing initialization. No poll-domain tables are introduced by this ticket.
- Permissions :: Exodan owns the state directory, identity, ownership and access policy. The app requires the supplied directory to exist and be writable; it does not create/chmod/chown infrastructure directories. Create its database with mode 0600 and preserve existing file modes. Never serve state paths as static assets. Local development instructions create an operator-owned temporary state directory.

*** Failure behaviour

- Startup failures exit 1 with safe context. Invocation errors exit 2; unknown flags are not ignored.
- Health uses a bounded store check and returns its small documented response. Detailed diagnostics remain in structured stderr logs with credentials and data redacted.
- Cancellation propagates to owned work. Successful draining exits 0; shutdown-grace expiry closes remaining connections and exits 1. Both paths release the database and emit safe structured stderr diagnostics.

** Architecture impact

*** Security impact

- Threat boundary :: First HTTP listener, filesystem state, and configuration inputs.
- Data and secrets :: Only synthetic/local configuration is needed for this delivery. No production secret is generated, committed, or displayed.
- Access :: Public landing page and minimal health only; no administrative, polling, filesystem browsing, or configuration-inspection route.
- Mitigation :: Contextual HTML escaping, restricted static paths, no raw Host-derived links, bounded requests, and deliberate state permissions.

*** Other relevant qualities

- Reliability :: Transactional migrations, bounded startup/health/shutdown, and fail-closed schema compatibility.
- Performance :: Small local service and bounded connections; this ticket makes no measured capacity claim.
- Operability :: README gains exact local prerequisites, build/run instructions, runtime keys, and failure recovery. Add =config/localhost.yaml.example= and a synthetic development example. Do not create live host files.
- Accessibility :: Semantic HTML, responsive CSS, keyboard focus, and Web-standard contrast; UT001.1 covers presentation.
- Portability :: Local Darwin development and Linux amd64 build, with IPv4 and IPv6 listener verification.
- Maintainability :: Standard =testing= and =httptest=, real temporary SQLite, injected clocks/roots when needed; no new browser test framework.

** Build and verification contract

Repeated installation updates only these managed paths, preserves unrelated files, and never installs plaintext secrets or host configuration. - Build :: Use module path =github.com/tigger-developer/Instant-Runoff-Polls-PR-STV-= and entry point =cmd/stv-poll=. Keep CLI help in =docs/stv-poll-help.md= and package it at build time; version output includes the build revision, or =dev= for an untagged local build.
